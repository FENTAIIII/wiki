# 管理员排障

## 玩家无法加入牌桌

检查：

- 玩家是否有 `doudizhu.play`。
- 牌桌是否已满。
- 玩家是否已经在另一张牌桌中。
- 指定桌名是否正确。
- 不指定桌名时，玩家是否在牌桌 12 格范围内。
- 如果是经济桌，Vault Economy 是否可用，玩家余额是否至少满足 `游玩费 + 基础赌注 × 2`。

## 三人坐齐但不开局

检查：

- 是否有玩家余额不足。
- Vault 是否正常启用。
- `wager-transactions.log` 是否触发冻结。
- 控制台是否出现“上一局尚未结清的 Vault 资金”。
- 管理员是否在正在进行中的桌上修改了经济状态。

## 玩家掉线或离开范围

插件会把局内玩家转为托管，本局继续。玩家回到牌桌范围后使用：

```text
/ddz return
```

如果提示必须靠近牌桌，检查：

- `player-session.tether-radius`
- `player-session.vertical-range`
- 玩家是否回到了原桌附近，而不是另一张桌。

## 托管无法立刻取消

可能原因：

- 本回合已经交给托管执行。
- 状态切换仍在 `state-cooldown-millis` 冷却中。
- 轮到托管后会保留至少 `trustee-delay-seconds` 秒，让玩家有机会回桌。

## 牌皮显示方框

检查：

- 是否安装 CraftEngine。
- 客户端是否正确加载资源包。
- `card-skins.yml` 的 `enabled` 是否为 `AUTO` 或 `TRUE`。
- 字体命名空间是否与资源包一致。
- `codepoint` 是否对应资源包内实际字形。

临时解决：

```yaml
enabled: FALSE
```

插件会回退普通文字牌。

## 没有语音

检查：

- `voice.yml` 的 `enabled` 是否为 `true`。
- 客户端是否加载了包含对应 sound id 的资源包。
- Minecraft 声音分类 `VOICE` 是否被玩家静音。
- 当前事件是否被 `chance` 概率跳过。
- 玩家是否在听众范围内。

## 排行榜没有数据

检查：

- 是否安装 PlaceholderAPI。
- 是否至少正常完成过一局。
- 占位符是否使用正确范围与字段。
- `stats.yml` 是否可写。
- 控制台是否提示 `stats.yml` 或 `stats.yml.bak` 无法读取。

## Vault 交易冻结

如果控制台提示欢乐豆交易冻结，不要直接删除日志重启。

正确处理：

1. 停止开放新经济牌局。
2. 备份 `wager-transactions.log`。
3. 根据日志中的 matchId、operationId、玩家 UUID、金额、状态，核对经济插件流水。
4. 找出只有 `INTENT` 的操作，确认它在经济插件中到底成功还是失败。
5. 人工修正玩家余额或确认无需修正。
6. 归档旧日志后再重新开放赌桌。

插件这样做是为了避免在不确定状态下自动重试，导致玩家余额重复增加或重复扣除。

## 强制取消一桌牌局

```text
/ddz stop <桌名>
```

强停会取消当前牌局，不记录胜负。经济牌局会尝试退回托管赌注与未确认游玩费。如果退款结果不确定，会进入冻结保护。

## 删除牌桌失败

如果牌桌正在游戏中，不能直接删除。先：

```text
/ddz stop <桌名>
```

牌局结束或取消后再：

```text
/ddz remove <桌名>
```
